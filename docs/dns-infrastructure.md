# DNS infrastructure evidence

Vector now reads CNAME, MX, NS and TXT records for public hostname inputs. These supply hosting-alias, inbound-email, authoritative-DNS and SPF authorization findings, each with its exact record, owner, TTL, resolver and collection date. Unrecognized records remain inspectable. An IP input never implies a company domain.

The collector sends four concurrent HTTPS requests to [Google Public DNS](https://developers.google.com/speed/public-dns/docs/doh/json), without an API key. Queries share three seconds, with 64 KiB and 64 retained records per response. TLS verification is always on, redirects/proxies are off, and the EDNS client-subnet parameter is set to zero. Cancellation removes active transfers. Local names and names resolving to nonpublic addresses skip collection. This metadata stage precedes the existing web budget.

CNAME uses the entered hostname. MX, NS and TXT remove an exact leading `www.`; other subdomains keep their own scope. No public-suffix guessing, arbitrary parent walk, recursive SPF include lookup or additional CNAME lookup is performed. CNAME chains already present in an answer are retained, up to eight links. Resolver errors, NXDOMAIN, empty answers, caps and timeouts are explicit. Answers must match the question and relate to its owner; unrelated answer records and authority/additional sections cannot create findings.

Initial general rules cover CloudFront, Vercel, GitHub Pages and Azure App Service aliases; Cloudflare/Azure nameservers; Google Workspace/Microsoft 365 MX targets; and those two mail systems' direct SPF includes. These rules apply to any queried hostname; there is no company inventory. Verification TXT tokens are retained as raw records and do not create a software finding. SPF is labeled sending authorization, not proof that an account is active or messages were sent. DNS configuration does not establish endpoint availability or its private backend.

## Provider zones added November 10, 2026

A Bybit inspection returned an Akamai edge alias, Amazon Route 53 nameservers, Mailgun mail exchangers and a Pardot SPF include, and none of them had a rule. `src/dns.cpp` now keeps three tables of provider zones (`alias_zones`, `nameserver_zones`, `mail_zones`). A record target matches only as a strict subdomain of a listed zone; the bare zone and lookalike names never match. Formats that are not a plain suffix are checked exactly: Route 53 (`ns-N.awsdns-NN` under `com`, `net`, `org` or `co.uk`), Google Cloud DNS (`ns-cloud-*.googledomains.com`), Amazon S3 website endpoints, Mailgun (`mxa`/`mxb`), Proton Mail, Yandex, SendGrid Inbound Parse, Amazon SES or WorkMail (`inbound-smtp.<region>.amazonaws.com`) and Zoho (`mx*.zoho.com|eu|in`).
