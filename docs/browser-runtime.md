# Browser runtime collection

Vector automatically executes the first eligible HTML page on each inspected web endpoint, and also attempts normal browser navigation after a rejected or failed static read in an installed Microsoft Edge or Google Chrome. The desktop remains native C++ / SDL3. A hidden Chromium process supplies page execution; Vector controls it directly from C++ through private Chrome DevTools Protocol pipes. No Python, Node, WebDriver or separately installed automation package is required to run Vector.

This closes a specific gap in static collection: JavaScript can insert script elements, invoke `import()`, load chunks from a CDN or initiate API requests after the original HTML has arrived. Vector observes those browser requests and applies its existing signatures to received script bodies. It also inspects the rendered DOM and a small set of explicit version-bearing runtime APIs. Paired React renderer properties on live DOM elements can identify production React without a global export; this evidence supplies no version. A library with no matching signature remains unidentified even when its script was collected. A fetched script does not, by itself, prove every statement in it executed.

If the independent browser document request fails but the static collector received a complete HTTP 200 HTML document for the exact URL, Vector makes one additional execution attempt using those already collected bytes. It retains the failed network attempt. The fallback has `document_source: captured_http`; its supplied document request has `collection: captured_http` and zero network transfer bytes. Script and subresource requests still use the browser network, and derived findings identify the captured-page context. CSP and other response security headers are preserved. Truncated bodies, errors, potentially truncated headers and unverified TLS without the existing opt-in cannot supply this fallback. Redacted static cookies are never replayed. The fallback shares the existing web deadline and browser request/page limits.

## What is retained

- Loaded script URLs and their initiating script when the browser supplies that information.
- Request method, resource type, HTTP status, remote address, MIME type, transfer size and completion/failure state.
- Evidence from script bytes, rendered markup and named runtime API/version registries. Each source is labeled.
- Vendor relationships backed by an **Observed response**, separately from static page references, policy destinations and code hints.
- Per-page browser state, main-document HTTP status, elapsed time, engine version, collected script count and limits reached. Browser HTTP errors remain explicit.
- Named technologies from selected browser response headers (server/framework/CDN identifiers), with exact matched values. Arbitrary headers and cookies are not exported.

**Evidence → Browser execution** displays runtime coverage, page results and an expandable request table. JavaScript coverage labels each script observation `static` or `browser`; the same URL can appear in both because these are distinct observations. Activity includes browser operations. JSON contains a `browser` section, `scripts[].collection` and runtime-aware coverage fields.

## Session and scope

Each page uses a new temporary profile. Vector does not open the user's browser profile, load extensions, reuse saved credentials or supply login information. Browser sandboxing and normal TLS verification remain enabled. Downloads are denied and authentication challenges are cancelled. The browser may send requests (including POST) and accept temporary cookies as the site's JavaScript runs. No request bodies, request headers, cookie values or URL query values are added to the runtime request report. Page-provided evidence may still contain sensitive identifiers in URL paths or code strings.

The original inspected hostname remains mapped to the selected IP. Website navigation can add or remove the exact `www.` hostname label. A redirected hostname resolves separately; when the static collector has already received its response, the browser pins that destination's observed address. Each web response retains its actual URL and remote address. This does not change the original endpoint or its port results. Dependency hosts use browser DNS. Unrelated top-level hostnames, disallowed ports and HTTPS downgrades remain blocked; HTTP-to-HTTPS on 443 is allowed. Subresources, frames and workers can load other origins. Printer port 9100 is excluded. No links are clicked, no forms are filled, and no scrolling or consent interaction is performed.

## Bounded coverage

The default observation window is 12 seconds per attempt. Collection uses that window even when the network briefly becomes quiet: deferred timers can start more script loads after page load. Cancellation, request/transfer caps and the shared web deadline still stop it earlier. Requests arriving during the final runtime inspection remain explicit, and unfinished requests prevent a complete-page label. Up to eight browser attempts (including captured-document fallbacks) are eligible, but all web collection shares a 30-second deadline, including static reads and browser startup. Browser control waits and active HTTP transfers are shortened to the remaining time. Profile shutdown and report analysis can add brief overhead afterward. The static crawler also shares a 12-page-attempt and 40-script-read cap across all ports; redirects and failed page requests consume that cap. The same canonical page URL is attempted once across endpoint queues and redirect chains. See [web evidence caps](web-evidence-cap.md).

Per page, collection permits up to 256 requests, 32 MiB of observed transfer data and 160 script bodies. A page that starts more than 256 requests has the excess refused; the admitted requests still finish and their scripts are analyzed until the normal deadline, and the page is reported as limited. Reaching the transfer budget ends the observation at once. Individual script analysis is limited to 2 MiB. Up to eight browser-loaded `text/css` responses per page are also analyzed for stylesheet signatures, retaining at most 512 KiB each. Their bodies come from the same bounded response stream; dependency hosts are eligible without additional fetches. The existing 4 MiB fallback retrieval bound applies when streaming is unavailable. Stylesheet outcomes, collection type and truncation appear in `stylesheets` and `stylesheet_coverage`. Chromium response streaming retains a contiguous prefix of at most 2 MiB even when the full bundle exceeds 4 MiB. The browser can continue executing the full bundle within the existing transfer/time limits. Interrupted responses retain an explicitly partial prefix. If streaming is unsupported or unavailable, the collector falls back to retrieving bodies of at most 4 MiB; larger bodies remain unavailable with a reason. Browser buffering can make a body unavailable, which is also recorded. Rendered markup is capped at 512 KiB when no document observer is attached, or 3 MiB when the endpoint/disclosure document observer is active. Reference analysis accepts that retained 3 MiB, up to 8,192 tags per document and 256 relationships per report. The total request list is capped at 1,024 rows. These are collection bounds, not a claim that the site has no further dependencies. Limits may have in-flight overshoot; the browser process tree is terminated at the end. WebSocket payloads, generated `eval()`/blob source and worker-only runtime globals are not inspected; worker network requests are collected when Chromium attaches their target.

Interaction-gated resources, late timers, blocked resources, login-only components, unrecognized/minified libraries, WebAssembly internals and private server dependencies are not a complete inventory. The browser does not defeat CAPTCHA or bot checks. Vendor contact does not establish account permissions, ownership or server-side access.

## Availability and CLI

Windows with installed Edge or Chrome is supported. If no executable is found, Vector retains static results and explicitly reports runtime `unavailable`. `VECTOR_BROWSER` may name an explicit browser executable (also useful for portable installs). A missing explicit path reports unavailable instead of silently falling back to another executable.

The desktop runs this automatically. The CLI offers `--no-browser` for static-only inspection and `--browser-timeout N` for a 1,000–30,000 ms observation window. Existing `--allow-untrusted-tls` explicitly applies to the browser too. Cancellation ends the dedicated browser process tree; temporary profile cleanup is attempted after shutdown. Other open browser windows are untouched. A normal Vector launch and demo mode make no target requests.

## Implementation references

- [Chrome Headless mode](https://developer.chrome.com/docs/automation-and-testing/headless): browser behavior without a visible web UI.
- [Chromium pipe switches](https://chromium.googlesource.com/chromium/src/+/refs/tags/133.0.6893.1/content/public/common/content_switches.cc): Windows pipe-handle transport.
- [CDP Network](https://chromedevtools.github.io/devtools-protocol/tot/Network/): request initiators, responses and body collection.
- [CDP Fetch](https://chromedevtools.github.io/devtools-protocol/tot/Fetch/): request interception and authentication handling.
- [CDP Runtime](https://chromedevtools.github.io/devtools-protocol/tot/Runtime/): rendered DOM and runtime API observation.

The browser component is original C++ code and reuses Vector's original detection rules. It does not embed a third-party fingerprinting corpus.


## Published-source discovery

The rendered document can also supply links and structured published-provider rows to the separate disclosure collector, up to 3 MiB of DOM text. The endpoint browser runs before collection of its linked disclosures so a disclosure page cannot use its initial execution time. One explicitly linked source can receive an additional browser observation of up to five seconds inside the shared web deadline. Its pages are marked `purpose: disclosure`; technologies used by that document are not merged into the inspected endpoint's software. Source URLs and their discovered link/redirect chain remain attached to collected provider evidence. This does not make published providers observed software or prove a complete company inventory. See [published-provider collection](published-providers.md).

Rendered script, frame, stylesheet and media elements also pass through the vendor detector. Their evidence remains **Page reference**, prefixed **Rendered DOM**, including captured-document provenance. Failed requests are not promoted to observed contacts. A request to a documented provider that failed at the connection (address, name resolution, refused, reset, closed, timed out or empty response) becomes a separate **Request attempt** relationship, shown in the overview as "Requested, no response"; see [tag-evidence.md](tag-evidence.md). Policy blocks and aborted loads add nothing, and inert templates, policy hints and code literals remain excluded from the overview. Disclosure-page resources remain separate from endpoint integrations.
